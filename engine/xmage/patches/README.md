# XMage patches

Changes to upstream XMage live here as `NNNN-description.patch` files (`git diff` format, paths relative to the XMage root). `build-xmage.sh` applies them in name order after fetching the pinned commit, and the build fails if one no longer applies.

Each patch needs a header comment that gives the reason, the upstream issue or pull request if there is one, and the condition for removing it.

At the current pin (`xmage_1.4.63V1`, since v0.9.4) there are twenty patches. Eight carry Two-Headed Giant: three from v0.5.0's spike, three from v0.5.1's card audit, one from v0.6.1 and one from v0.6.2; one, from v0.6.1, lets a computer player control a turn in every format; one, from v0.8.5, gives each game its own random generator; one, from v0.8.7, carries King's Table ([King's Table](../../../docs/kings-table.md)); one, from v0.9.0, fixes Weathered Sentinels in every format; three, two from v0.9.4 and one from v0.9.5, teach XMage cards that Commander Duels' packs deal and XMage lacked ([the catalog](../../../docs/catalog.md#stand-ins-v062)); and two from v0.9.8: one lets a seat choose any defender its combat names, whatever the range, and one bounds the copies of the game a simulation makes for a triggered ability's options. Two from v0.9.9 let a game be recorded and taken up again ([recording and recovery](../../../docs/engine/recovery.md)): one resumes a saved game in the middle of a turn, one makes the last cards whose state Java could not write writable. One from v0.9.10 lets a game's own process read the card database its engine's front process serves without writing to it ([each game in a process of its own](../../../docs/engine/isolation.md)). See [the Two-Headed Giant note](../../../docs/engine/two-headed-giant.md), and [the audit's review](../../../docs/engine/two-headed-giant-audit.csv) for every card it looked at.

**Moving to 1.4.63 (v0.9.4).** The twelve patches of 1.4.62 were rebased one commit each onto the new tag. Three needed a hand: XMage 1.4.63 reworked creatures put onto the battlefield attacking (508.4) into `Permanent.setEntersAttacking` and `Combat.addEnteringAttackers`, so 0004's change to `TokenImpl` is gone and its rule (each player of the active team is an attacking player, 805.10a) now sits in `addEnteringAttackers`; 0009's Ellie, Brick Master keeps the attacking player of the trigger in the new token call; 0007 merged by itself. The engine suite passed unchanged on the new pin.

Patches 0008, 0010, 0012 and 0017 are not Two-Headed Giant's: they apply in every format. 0013, 0014 and 0015 only add cards (and, in 0014, an ability and a counter type no other card uses), so no card XMage already had plays differently. 0011 is King's Table's: every default it adds returns what XMage did before (allies are the teammates, the attack option's players are the attackable ones, no combat across range, one starting life for everyone), so other formats play as before; the one change outside King's Table is that the cards reading "your starting life total" ask the game for that player's, which every other game answers with its one starting life. 0008 and 0012 change how Legacy and Commander play (a bot's control of a turn now works; Weathered Sentinels plays as printed, and a seat is offered only the defenders its attacker can attack, `WeatheredSentinelsTest`); 0010 changes only which generator a thread draws from. 0017 changes what a bot's search looks at, in every format, only where a triggered ability has more than twelve options: there it scores the line by twelve of them (`FairBotMemoryTest.aTriggersOptionsAreSampledNotAllCopied`). 0016 belongs to King's Table too: `TargetDefender` offers the defenders the combat names in place of those among them in the attacking player's range, and in every other game the combat names only defenders in range, so the choice is the same there (`KingsTableTest.theChoiceOfADefenderOffersEveryDefenderTheCombatNames`, `KingsTableAttackChoiceTest`). Every game type other than Two-Headed Giant names no teammates, so XMage behaves as unpatched for Legacy and Commander: each change reduces to XMage's own code without teammates, all engine tests that predate the patches pass unchanged, and `TwoHeadedGiantAuditTest.aLegacyDuelPlaysAsBefore` and `aLegacyDuelPlaysTheReviewsPatternsAsBefore` play the audited patterns in Legacy duels, and `TwoHeadedGiantRareCardsTest.aLegacyDuelPlaysTheFixedCardsAsBefore` the cards of 0009 whose code outside team games was rearranged.

0018, 0019 and 0020 change nothing in how any game plays (0020 only what a game's own process does as it opens the card database): 0018's watcher is set only by a recorded game, its resume is called only when one is taken up, and what it leaves out of a saved object is what XMage's own copies never read (every engine test that predates it passes unchanged); 0019 only makes classes serializable (`SerializableCardsTest`).

To change a patch: apply them in order to the pinned commit in a scratch clone, one commit each; make the change as a fixup of the patch it belongs to and fold it in (`git rebase --autosquash`); then write each commit's `git diff` under its patch's header. The image the engine build makes has the compiled XMage in `/xmage/m2`, so a container from it can rebuild only the changed modules and run the engine tests against them.
