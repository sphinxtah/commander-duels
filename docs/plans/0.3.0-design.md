# v0.3.0 design: the Magic Duels table

The technical design for [the v0.3.0 plan](0.3.0.md), written on 2026-10-20 before any of it was built: three independent designs (accessibility and testing first, rendering first, Magic Duels fidelity first), scored and merged into this one by a judge. Repository paths are relative to the repository root. The binding source is the plan, from "What the screenshots show" through "Decisions at the start of v0.3.0" and its build order. Where the code ends up differing from this design, the code and [the game screen](../game-screen.md) describe what was built.

Facts re-checked in the repository and in the installed `pixi.js@8.22.0` while judging:

- `pixi.js` main entry (`lib/index.mjs`) imports `./rendering/init.mjs` (sprite, graphics, mesh, text pipes, `ImageSource`, `CanvasSource`) but only *exports* the accessibility and events modules. `AbstractRenderer.init` calls `loadEnvironmentExtensions(skip)` with `skip = options.manageImports === false`; `browserAll.mjs` is what registers `AccessibilitySystem`, `EventSystem`, DOM and filters. So `manageImports: false` keeps Pixi's accessibility layer (whose `activateOnTab` defaults to `true` and would grab Tab) and event system out entirely. Filters are then unavailable too, so the scene uses none.
- `lib/scene/mesh-perspective/PerspectiveMesh.mjs` exists (with `setCorners`); `ImageSource.test` accepts `ImageBitmap`; `package.json` exports `./unsafe-eval` → `lib/unsafe-eval/init.mjs`; `loadTextures.config.preferWorkers` defaults to `true` (`loadTextures.mjs:37`).
- `PromptPanel.tsx:153-176`: the focus rule looks only inside the panel and prefers `[data-first]:not(:disabled)`, so a Stop Timer button placed inside the section after the primary keeps F1–F3.
- `PromptPanel.test.tsx:228` uses `toHaveTextContent("Pass priority")` (a substring match), so a primary labelled "Continue" with a visually hidden "(Pass priority)" passes unchanged.
- `PriorityPanel.tsx:45-57`: Escape-stops-a-pass lives in the panel's own effect, so the panel must stay **mounted** for PR5 to work while its drawer is closed.
- `GameScreen.tsx:156-183`: the P key reads `onScreen` written in `useLayoutEffect`; the timer reuses it.
- `model.ts:152`: `all_attack` reads "Attack with everything"; `optionText` prefers the engine's label when present.
- `PromptKind` includes `choose_defender` and `choose_target` (`types.ts:8-24`).
- `api/schemas.py:307-314`: `GameSeat.handle` is in the game summary; `Me.handle` exists. Sigils can be seeded from handles, so every viewer derives the same sigil for a player.
- CSP (`web/nginx.conf:30`): `style-src 'self'` (React's CSSOM style writes are allowed, `style=""` markup is not), `img-src 'self' data:`, `connect-src 'self' …`, no `worker-src`.

## 1. Scores

| Design | Fidelity | Inventory | A11y/test | Rendering | Security | Simplicity | Overall |
|---|---|---|---|---|---|---|---|
| 1 a11y-test | 6 | 9 | 9 | 7 | 9 | 8 | **7.5** |
| 2 render-perf | 7 | 7 | 7 | 9 | 9 | 7 | **7.0** |
| 3 fidelity | 9 | 8 | 7 | 7 | 8 | 5 | **7.0** |

- **Design 1** has the cleanest architecture: one pure layout drives both pictures; `GameContextValue`, `GameState` and `PromptPanel`'s structure are untouched; a `dom` painter makes jsdom and no-WebGL work without mocks; a fake-WebSocket journey tests every size without the engine. Weaknesses: a top bar and boxed rail that Magic Duels does not have; flat card sizes; a risen hand card whose click falls through to the land underneath (a real UX bug); less rigorous Pixi set-up (Pixi's EventSystem still loaded).
- **Design 2** has the best renderer: verified Pixi initialisation (`manageImports:false`, `preference:["webgl"]`), resolution maths (`devicePixels/designW`, capped), on-demand rendering, texture tiers decoded with `createImageBitmap(resizeWidth)`, memory budget, context-loss recovery, Web Locks for the live-game gate. Weaknesses: the Priority drawer is unmounted when closed (breaks PR5 Escape-stop-pass); the log is hidden when closed (no announcements); the timer keyed by revision; the rise click falls through.
- **Design 3** is the most faithful: perspective size law `s(y)`, the band HUD instead of a bar, Magic Duels' labels and icons, card anatomy, emblem rules, step captions, a detailed sound table, the teleport/redirect pointer rule. Weaknesses: geometry conflicts (the stack's top card overlaps both front rows; the revealed plate and practice notice cover interactive cards), a "More choices" fly-out that hides options from tests and the e2e strict locators, a centre plate outside the prompt's scroll box, edits to `Inspection.tsx`, unconstrained chained drag answers.

## 2. The chosen architecture, and what was grafted

**Base: Design 1's architecture.** A pure `buildTableModel` → `layoutTable` produces one `TableLayout` in 1920×1080 stage units (su). Both pictures draw from it:
- a **DOM layer** of real, named, transparent buttons at the layout's hit rectangles (all input, focus, names, `data-*` hooks), inside a 1920×1080 box scaled with one CSS transform;
- a **PixiJS scene** on a full-viewport canvas behind it (`aria-hidden`, `pointer-events:none`).
Two painters: `webgl` (Pixi draws faces; DOM buttons transparent) and `dom` (no Pixi; the DOM paints faces with `CardFace`, sigils with SVG, diamonds with CSS). jsdom, no WebGL, context loss and the "Plain table" setting use `dom`. The protocol, `connection.ts`, `types.ts`, `GameState` and `GameContextValue` do not change.

**Grafted from Design 2:** the renderer and its internals (Pixi init options, `StageFit` and resolution maths, canvas outside the transform, render on demand, `Timeline` retargeting from current poses, texture tiers and budget, context-loss handling, unmount order, the dev bench), shared `images.ts`, Web Locks for the live-game gate, `duelsLabel` with a hidden suffix so existing tests pass, the "any key engages" timer rule, zone browsers as drawers (also the plan's Build order step 5), `game=` left out.

**Grafted from Design 3:** the visual table (perspective size law, band HUD, rows nearest/behind the band, opponents' zone tiles top-left, pedestals, tag/pip/badge anatomy, step captions and phase pips, emblem rules, line rules), the pointer rule that keeps a risen hand card clickable without growing its DOM box, the sound recipe table, the dev-only table lab, the timer's arming and resume floor, the opponent sigil grey and seeds from handles.

**Kept from Design 1 beyond the base:** the timer's key (`prompt id | top object`), the 36-su minimum hit and pile cap of 5, the live-game route guard for `navigate-existing`, the log kept in the accessibility tree while closed, the T13 DOM and image-request checks, the fake-table journey.

### 2.1 Conflicts, resolved

| # | Conflict | Decision | Why |
|---|---|---|---|
| C1 | Top bar (D1), system strip (D2), band HUD (D3) | **Band HUD**: diamonds on the band's left (Game menu, Log, Priority, Full screen, Inspection). "← Table" and Concede live in the Game menu. | Magic Duels has no bar; the band already carries the turn. |
| C2 | Flat sizes (D1/D2) vs perspective `s(y)` (D3) | **`s(y) = (y+1620)/2700`**, uniform per row, with per-arrangement column factor `c`. Rows re-placed (§8) so every hit is disjoint (D3's numbers overlapped the stack). | Fidelity; cards still upright and evenly scaled. |
| C3 | Risen hand card: no growth, click falls through (D1/D2) vs redirect (D3) | **Redirect, guarded**: DOM box never grows; a click on another table button inside the risen picture goes to the risen card only if the pointer dwelt there (≥3 `pointermove`s inside the grown rect, or ≥150 ms). Synthetic one-move clicks (Playwright) are never redirected. | Fixes the UX bug without breaking hit-testing. |
| C4 | Options in a hidden "More" fly-out (D3) vs all in a scroll column (D1) | **All options rendered in the prompt section**, scrolling: lead diamonds (primary, `all_attack`, Stop Timer), then today's groups. No hidden fly-out, no centre plate. | Keeps PromptPanel tests, the e2e strict locator "Pass until your next turn", F1–F3. |
| C5 | Priority drawer unmounted (D2) vs mounted (D1/D3) | **Mounted, `hidden` when closed.** | PR5 Escape works while closed. |
| C6 | Log drawer hidden (D2) vs visually hidden (D1/D3) | **Visually hidden when closed**, `tabIndex=-1`; `role=log` still announces. | LG1 and screen readers. |
| C7 | Zone browser: modal dialog (D1/D3) vs drawer (D2) | **Drawer** (`ZoneBrowser` with `ZoneContents`), non-modal; also hosts the battlefield, pile, stack and hand browsers. | Plan Build order step 5 ("drawers … the zone browsers"); P key and answering still work while browsing. |
| C8 | Timer key: prompt+revision (D2), prompt id (D3), prompt id + top object (D1) | **`${prompt.id}|${stack[0]?.id ?? attack:turn:step}`**. Same key across revisions carries on; a new top object restarts. | A republish must not restart; a new spell must. |
| C9 | Timer stop triggers | **Stop (for this key)**: Stop Timer, T, Space, any non-modifier key except Escape, any pointerdown on a stage control, opening a menu/drawer/dialog/browser, a drag. **Pause** (resume ≥2 s): tab hidden, window blurred, a command pending, phase not open. Hover never matters. | Keyboard and screen-reader players are never passed for while acting (D2), and D3's floor. |
| C10 | Timer lengths | **Off, 5, 8 (default), 15, 30, 90 s.** | 90 s ≥ 10× default (WCAG 2.2.1). |
| C11 | Live-game gate: BroadcastChannel (D1/D3) vs Web Locks (D2) | **Web Locks** `cd-live-game:<id>`, checked by the page and again by the worker; missing API ⇒ treat as live. | Released automatically when a tab crashes or closes. |
| C12 | Chained drag intents (D3) vs never auto-answer (D1) | **Allowed, constrained**: only `choose_defender` after an attack drop on a seat and `choose_target` after a block drop on an attacker; within 2 s; exactly one option matching the drop; answered by the `choose` of the render that drew that prompt. | The drop already named the choice; A2 still binds. |
| C13 | Token grouping: any equal permanents (D1/D2) vs tokens + lands (D3) | **Lands piles** and **token groups** only; nontoken nonland permanents never pile. | Magic Duels stacks identical lands; UI02 names tokens. |
| C14 | Pile members: all slices (D2) vs cap (D1) | **Show ≤5 members** (strips ≥36 su); "+N" opens the pile browser. | Hit size; journeys fall back to the column's `[data-option]`. |
| C15 | Opponent P/T tag at top outside (D3) | **Over the printed box, both sides.** | The plan's default decision. |
| C16 | `game=` printing for own cards (D2) | **Not in v0.3.0.** | Not decided; changes Card.test URLs and cache keys. |
| C17 | png missing memory keyed by size (D2) vs name (D1/D3) | **Name only**; the server serves `large` (then `normal`) for `size=png` when no png exists and records nothing. | Card.test test 6 unchanged; no week-long blank. |
| C18 | Graveyard/exile access | **Zone tiles are buttons** ("Graveyard N", "Exile N", "Command N · Tax T"); count diamonds are non-interactive spans. Your command cards are also `CardButton`s. | One target per zone; commander click to cast. |
| C19 | Practice notice, alerts, revealed cards placement | Notice and passing notice at the **top of the prompt column**; revealed/looked-at rows **inside the prompt section** (as today); alerts on a plate over the opponents' area (only while the table cannot be played). | No overlay over interactive cards. |
| C20 | SysOp face-up hands on the table (D3) | **Not added**; the Inspection drawer keeps SI1–SI4. `Inspection.tsx` unchanged. | Scope; SysOp still sees everything. |
| C21 | Status text, names, life numbers: canvas (D3) vs DOM (D1) | **DOM text** for anything that does not travel with a card; Pixi for frames, faces, tags, pips, glows, curves, emblems, floating numbers. | Crisp at every scale, Larger text, `getByText` tests. |
| C22 | Stack orientation | **Top item centred at (960,510)**, older items fan left behind it. | Magic Duels: the spell lies mid-band. |
| C23 | Phone width | Table renders at its scale floor with a non-blocking note below 1280×720; game phone CSS deleted; other pages keep 390 px. | Plan: phone layout retired. |
| C24 | Expand board | Compact opponents expand **in place** (others become chips); the duel opponent and you open the **battlefield browser** drawer; overflow "+N" opens it too. A new prompt that offers an object of a chipped opponent collapses the expansion. | Every offered object always has a hit. |

## 4. The shared contract: `web/src/game/table/types.ts` (WP0)

Types and constants only. Implementations declare themselves with these aliases (`export const layoutTable: LayoutTable = …`).

```ts
// web/src/game/table/types.ts — v0.3.0 shared contract (WP0). Types and constants only.
import type {
  CardView, CombatGroup, GameView, ObjectId, PlayerView, PriorityControls,
  Prompt, PromptOption, Seat, Snapshot, StackItem,

import type { Located, Zone } from "../model";

/* ---------- stage units ---------- */
export const STAGE_W = 1920;
export const STAGE_H = 1080;
/** Stage unit: 1 su = 1 CSS px of the 1920×1080 stage at scale 1. */

export interface Point { x: SU; y: SU }
export interface Rect { x: SU; y: SU; w: SU; h: SU }
export interface Diamond { cx: SU; cy: SU; side: SU }   // a square turned 45°; bounding box side·√2

export type Arrangement = "duel" | "three" | "four";
/** offered: purple glow + ◆; playable: hand card with an answerable play/cast (pink + ◆);

export type Mark = "none" | "offered" | "playable" | "selected";
export type Painter = "webgl" | "dom";
export type MotionLevel = "none" | "normal" | "fast" | "faster";
export type CardImageSize = "normal" | "large" | "png";
export type ZoneName = "graveyard" | "exile" | "command";
export type DragKind = "play" | "attack" | "block";

/* ---------- table model ---------- */
export interface TableCard {
  key: string;                    // `${zone}:${id}`, stable while the object stays in its zone
  id: ObjectId;                   // the DOM button's data-card value (card id, or stack item id)
  card: CardView;                 // stack items get a synthesised CardView; hidden ⇒ { id, hidden: true }
  located: Located;
  zone: Zone;
  ownerSeat: Seat | null;
  controllerSeat: Seat | null;

}
export type UnitKind = "single" | "lands" | "tokens" | "host";
export interface TableUnit {
  key: string;                    // group key, or the single card's key
  kind: UnitKind;
  cards: string[];                // TableCard keys, bottom → top (top drawn last, gets the full hit)
  attachments: string[];          // kind "host": drawn behind, peeking right
  row: "front" | "back-lands" | "back-other";
  tapped: boolean;
}
export interface CommanderInfo {
  name: string; zone: string; objectId: ObjectId | null; tax: number;
  damageDealt: { seat: Seat; damage: number }[];
}
export interface TablePlayer {
  seat: Seat;
  player: PlayerView;
  anchored: boolean;              // drawn on the bottom half (you, or the spectator's lowest seat)
  name: string;                   // "You" or the name (P1, L7 observer wording)
  title: string | null;           // your deck name for yourself; "Bot"/"Player" otherwise; deck name only for SysOp
  kind: "human" | "bot" | null;
  sigil: { seed: string; grey: boolean };   // seed: `handle:<h>` | `bot:<seat>` | `seat:<seat>`
  active: boolean; priority: boolean; lost: boolean; won: boolean;
  offered: PromptOption[];        // bySeat (P3)
  mark: Mark;
  targetLabel: string;            // P3 "<name>: N life. <options>" (or "N life" when no options)
  sideLabel: string | null;       // anchored: "Your side of the table" | "<name>'s side of the table"
  articleLabel: string | null;    // opponents: "<name>, seat N"
  battlefieldLabel: string;       // "Your battlefield" | "<name>'s battlefield"
  units: TableUnit[];             // battlefield units in row order
  graveyard: string[]; exile: string[]; command: string[];   // card keys, top last
  commanders: CommanderInfo[];
  commanderDamageTaken: { fromSeat: Seat; commander: string; damage: number }[];
}
export interface TableStackEntry {
```

### 6.1 Snapshot → screen

```

GameScreen render: snapshot, view, prompt, canAnswer, observing, answer(promptId, revision)   unchanged (A1, A2)
 ├─ context: GameContextValue (same shape and deps; preview() now writes the ui store)
 ├─ fit      = useStageFit()                            CSS vars only on resize; no board re-render
 ├─ settings = useTableSettings();  motion = useMotionLevel(settings.animationSpeed); largeText = useLargeText()
 ├─ painter  = settings.painter === "dom" || !probeWebGL() || scene failed/lost ? "dom" : "webgl"
 ├─ {model, layout} = useTableModel({input, expandedSeat, textScale})   memo on [snapshot, context, …]
 ├─ diff     = useTableEvents(model, state.phase)        previous model kept in a ref set in useLayoutEffect
 ├─ timer    = useResponseTimer(timerInput, ui, onExpire)
 ├─ useTableSound({diff, layout, settings, viewSeat, refusal, timer: timer.view})
 ├─ holdLiveGame(gameId) while snapshot && !result && !state.ended
 └─ <Stage fit painter status canvas={painter==="webgl" && <SceneHost frame fit motion ui onStatus/>}>
       <TableContext.Provider>
```

### 6.3 Pointer rules (`pointer.ts`)

1. The canvas has `pointer-events:none`; regions (sections, articles, rows, the stage) have `pointer-events:none`; only leaves (buttons, menus, links, inputs, drawers, the column) take pointer events.
2. Hover dwell 80 ms before `hover` is set; leaving all targets clears after 150 ms (V4 fixed: `preview(null)` clears).
3. **Rise** (hand cards): set when the pointer is inside a hand slice, or a hand card has keyboard focus (`source:"focus"`). A pointer rise is kept while successive `pointermove`s stay inside the grown rect and each moves ≤ 64 su; a jump > 64 su re-evaluates from scratch. A rise is dropped when its card leaves the hand.
4. **Redirect**: a capture-phase `click` whose target is a table control (`[data-card]` not in the hand, `[data-player]`, zone tile) inside a pointer-risen card's grown rect is redirected to the risen card (`preventDefault`, `stopPropagation`, activate) only if ≥3 `pointermove` events were inside the grown rect since the rise, or the pointer entered it ≥150 ms ago. Menu items, the column, HUD, drawers and dialogs are never redirected. Playwright's single move before a click never qualifies.
5. The magnifier, the drag ghost, emblems and floating numbers are canvas or `pointer-events:none`.
6. Wheel over a card: up → magnifier level 2, down → level 1 then off (`preventDefault` only over cards).

## 7. Stage, scaling and resolution

- `k = max(1/4, min(cssW/1920, cssH/1080))`; `ox = round_dp((cssW − 1920k)/2)`, `oy` likewise (rounded to device pixels). `designW = cssW/k`, `designH = cssH/k`.

Focus outlines `calc(3px / var(--stage-k))` so they render ≥3 CSS px. Dialogs (top layer, outside the stage) set `font-size: calc(1rem * max(1, var(--stage-k)))`.

The stone extends into letterbox margins (ultrawide shows more table). Pixi's auto-resolution text re-renders on `resolutionChange`.

### 8.11 Row packing and invariants

- Unit widths: single W (H when tapped); lands pile `W + (k−1)·max(0.24W, 36)`; token group same; host `W + m·max(0.24W, 36)`; + pip margin. Gap 0.08W. Back row = lands units, a 0.5W gap, other units.
- Fit: (1) natural widths fit → centre in the row's range; (2) else shrink cards by `f = max(0.72, avail/total)`; (3) else overlap units uniformly keeping ≥ `max(0.30·footprint, 36)` visible each; (4) else reserve 56 su at the row end for "+M" (battlefield browser) and leave the rest without hits.
- Piles show ≤5 members with hits; beyond, "+N" (pile browser).
- Overlapped units: hit = visible strip `[x_i, x_{i+1})`; the last unit gets its whole footprint; later units draw above.
- Combat ordering: during `declare_blockers` and later combat steps, the defender's blocking front-row units are ordered by their attacker's x.
- **`validateHits` invariants** (tested on every fixture × textScale 1/1.25, and on 300 seeded random boards per arrangement: 0–40 permanents per player, tapped, attachments, tokens, a 0–8 stack, 0–25 hand):
  1. every interactive hit lies inside 0–1920 × 0–1080;
  2. all interactive hits (cards, more, tiles, player targets, Expand/board buttons, HUD diamonds, the column box) are pairwise disjoint;
  3. every hit is ≥ 36×36 su (hand slices ≥ 40 wide);
  4. DOM order within each row equals x order;
  5. every object in `view.hand`, `view.battlefield`, `view.stack` and your command zone is exactly one node with a hit, or is counted by exactly one "+N";
  6. the same model gives the same layout;
  7. tag rects end ≤ 0.935H and pips lie outside the image.
  Excluded: drawers, menus, the Game menu, the magnifier, alerts (user-opened or shown only while the table cannot be played).

## 12. The response timer (WP5)

**Eligibility** — `timerKey(input)` is non-null only when all hold:
1. `prompt.kind === "priority"` and `primaryOption(prompt)?.action === "pass"`; `status === "your_prompt"`;
2. `canAnswer`, not observing, role controller, phase open;
3. `seconds > 0`;
4. `controls.full_control === false` and `controls.passing === null`;
5. a response moment: (A) `view.stack[0]` exists and `controller_seat !== view.seat`; or (B) empty stack, `view.active_seat !== view.seat`, `view.step ∈ {declare_attackers, declare_blockers}` and some combat group has attackers.

Never on mulligan, targets, modes, amounts, piles, ordering, payment, attackers or blockers (the forced choices), on your own object on top (holding priority), at an empty-stack stop, while passing, in full control, in a watching tab, or for SysOp observing.

**Key:** `${prompt.id}|${view.stack[0]?.id ?? `attack:${turn}:${step}`}`.

| From | Event | To |
|---|---|---|
| idle | new eligible key | arming (`armedAt = now`) |
| arming | `settledRevision ≥ revision`, or `armCapMs` elapsed (1200; 0 with motion `none` or the `dom` painter) | running (`endsAt = now + seconds·1000`) |
| running | hidden, blurred, pending, phase ≠ open | paused (`remaining = endsAt − now`) |
| paused | all clear, same key | running (`endsAt = now + max(remaining, 2000)`) |
| arming/running/paused | Stop Timer, T, Space; any non-modifier keydown except Escape; pointerdown on a stage control; a menu, drawer, dialog, browser or zoom opens; a drag starts | stopped (for this key, for good) |
| running | `now ≥ endsAt` | expired → `onExpire(key)` once |
| any | key changes | idle → arming for a new eligible key |
| any | lease lost, result, `seconds` set to 0 | idle |

- **Expiry** answers `{option_id: primary.id}` through `onScreen.current` only if the on-screen input still gives the same key and `canAnswer`; a refused (stale) answer is silent. The timer never sends `set_priority` or a `pass_until_*`, never cancels a pass mode, never answers anything but the pass. The engine's window is unaffected (UI07).
- After "Play here", a still-open eligible prompt gets a fresh full timer.
- **Display:** Pixi purple bar by your portrait (DOM bar in `dom`); the Continue ring; `data-timer`/`data-remaining` on the timer element; ticks in the last 3 s; one polite announcement per key: "<subject>. Continuing in 8 seconds. Press Space or T to stop the timer."
- Progress is written to the store at 10 Hz; React re-renders only on phase changes.
