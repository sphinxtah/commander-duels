# v0.3.0: the Magic Duels table

A minor version, opened on 2026-10-20. The game screen during play is made to look like Magic Duels, with Commander and this site's own features added, following [the v0.3.0 plan](../plans/0.3.0.md). The owner added three things at the start: full screen at 1080p, 1440p and 4K; an installable app with its own desktop icon, offered to signed-in players in the browser; and a magnified card under the pointer or the keyboard's focus.

## Scope agreed for this version

Agreed on 2026-10-20 (details in [the plan](../plans/0.3.0.md#decisions-at-the-start-of-v030)): a WebGL table drawn with PixiJS, with a structured DOM layer for the keyboard and screen readers; generated sigils as portraits until the owner's Planeswalker portraits arrive; Magic Duels' response timer with Stop Timer; opponents in a row across the top at three and four players; full screen when a game starts, on PC screens from 1280 × 720 to 4K, with the phone layout of the game screen retired; the installable app with an install banner, a desktop icon and safe updates; the magnifier as Magic Duels does it; and animation, token grouping, drag and drop, and generated sound effects.

## Changed

- **A sign-in landing page before the app**, at the owner's request ([identity](../identity.md#before-the-app-the-landing-page-v030)). Until an account is active, every address shows only the owner's wordless CD mark with the Google sign-in button below it: no words above the button, and no sidebar, navigation, top bar, banner, footer or install banner. The address is kept, so the screen it names opens after sign-in and approval, and a game's address opens no table. An account waiting for approval sees a plain page with its email address, Check again and Sign out, which notices the approval by itself; it chooses its handle once approved. A denied account sees that it was not approved. SysOp's entrance stays at `#sysop` on its network, under the mark. A service that has not answered in 7 seconds leaves Try again to press, never the mark alone, and a new account is pointed to Profile for its handle once approved.
- **The Cards page hides cards that cannot be played here yet**, at the owner's request. It opens on playable cards; "Show cards not playable yet" beside the count, the "Playable here" filter, or a search that names playability (`is:unsupported`, `status:catalog_only`) shows the rest, labeled as before (T18). "Clear filters" goes back to playable cards ([the card catalog](../catalog.md#statuses-cat06cat09)).
- **The card dialog names the illustrator** of the image on show, and Wizards of the Coast's copyright, as the game zoom does. The card search's image reference carries the artist for it (`CardImageRef.artist` in the API contract), and a card's details take `?printing=<id>`, so a deck entry pinned to an older printing than the 60 listed first is listed, shown and credited too.

## Fixed

Reported by the owner on 2026-10-20 with a screenshot of the Cards page, then swept for the same faults across the client; each finding was reproduced in a browser and survived two skeptics before it was fixed:
- **Oversized cards on the Cards page.** A tile's caption never wraps, and its inner grid column grew to the caption's width, so a long name (a double-faced card's two names, but also Swords to Plowshares or Kenrith, the Returned King) widened the tile and its image over the next columns, made the row taller and the page scroll sideways. The column now keeps the tile's width, and long names end in an ellipsis, with the full name on hover.
- **Card images altered against Scryfall's rules.** Not-playable cards were desaturated and darkened; the image now shows as served, and the caption turns amber. Catalog images were cropped by a fraction of a pixel; they now fit exactly and are never cropped. On the game screen, the sticky bar blurred the cards scrolling under it (it is now opaque), and a tapped card's action mark covered the artist line (it now sits over the name).
- **The deck editor** let one long row (a long name beside a long mana cost, such as Progenitus's) widen the deck column and scroll the page sideways at 981–1200 pixels; rows now wrap.
- **The search help** scrolled sideways in a narrow dialog (phones, or Large text); its terms now stack above their descriptions.

Found through CI run #44's failed deck journey, then a hunt for every intermittent failure, each reproduced and its fix verified by repeated runs:
- **A deck chosen for the practice table could be cleared.** Opening the table asked for its options twice under React's StrictMode (the development build the browser journeys use), and the second answer, landing late, reset the deck the "Play it" link had chosen. The table now ignores the answers of a mount that has gone, and resets the deck only when the format changes, not when a copy of the same options arrives (CI #44; it failed 5 runs in 25 under random delays, none in 175 after).
- **The deck editor could put back the deck as it opened** when StrictMode's second request for it answered after the first edit; the autosave would then have saved that. Only the mount that stays fills the editor now.
- **The decks list could show another tab's decks** when the list asked for after an archive, restore or delete answered after the player had moved to another tab.
- **A sign-out could be undone** by an answer already on its way: an approval check on the waiting page, an account check started by going back online or Try again, or a preferences save. Answers asked for before the latest change of account are now dropped, and that check's CSRF token is applied only with an answer the page uses.
- **A dropped network left errors unhandled** (and the card search on "searching…" for good): the API client now turns a request the network never answered into the service's own "unavailable" answer, which every screen already handles.
- **Focus could rest on the page's body for a moment** after a sign-in, a sign-out or a change of screen, because it moved in an effect React runs after drawing; it now moves as the new screen is drawn. The page's route attribute does the same, so the landing page never shows with the table's layout.
- **The unit tests** no longer let one test's page, storage, address or fake clock reach the next (the shared setup unmounts before a test file restores its mocks, clears both storages, waits out jsdom's late hashchange and drops fake timers), and timing checks measure the code rather than the machine's load. 32 consecutive full runs, and 86 in the verification (38 shuffled), passed without a failure.
