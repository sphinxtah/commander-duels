# v0.8.1: the campaign's content in the API image, and its music

A patch version, opened and closed on 2026-10-31, the night v0.8.0 deployed. The next version is v0.8.2 ([the plan](../plans/0.8.2.md), opened at v0.8.0's close as the plan for v0.8.1).

## Scope agreed for this version

The Campaign page on the live site said "The campaign could not be opened." The API image copies its content files one by one, and v0.8.0 left `content/campaign.json` out of the list, so the API answered 503 `campaign_unavailable`. Asked whether the fix should ship as v0.8.1, the planned version becoming v0.8.2, the owner, 2026-10-31: "Yes, lets call it v0.8.1. Lets also add an audio track to the campaign cut scenes. It's in the campaign folder and named camapaign.audio.mp3. That should be playing in the background during the dialogue parts between battles. When you're finished with v.0.8.1, close it, commit it, and push it to Github." (The file is `campaign.audio.mp3`.) Then: "Make note that v0.8.2 will be next, in the next chat. I added more song files to the music folder to be added to the playlist."

Until v0.8.1 deploys, the live API can be given the file by hand: `docker cp content/campaign.json commander-duels-api-1:/app/content/campaign.json` and `docker restart commander-duels-api-1`, which lasts until the container is recreated.

## Fixed

- **The API image holds `content/campaign.json`**, so the campaign opens on the live site.
- **And `content/print-runs.json`**, left out the same way since v0.5.1: packs on the live site dealt serialized printings without their print runs' limits ([print runs](../shop.md#print-runs-v051)). They follow them from this version. Copies dealt before stay where they are.
- `tests/test_api_image.py` checks the API image copies every content file the API reads.

## Added

- **The cut scenes' music** ([the campaign](../campaign.md#the-cut-scenes)): the owner's track (32 minutes) under every cut scene between the duels, fading in and out with each scene and going on from where it stopped at the next. The menu playlist holds its place meanwhile and plays on after (`MenuMusic.hold`). It plays at the menu music's level and mutes; the cut scene's Music button and Story settings' "Music in the cut scenes" turn it off. Like the other music it is not in this repository: the private repository's `music/campaign.mp3` reaches the live site in the private web image, which serves it at `/music/campaign.mp3`; locally, `music/campaign.mp3` beside `compose.yaml`.

## Changed

- **The playlist has twenty-six songs**: the private repository's `music/` holds tracks 22 to 26 (Nine Inch Nails' The Perfect Drug, Snoop Dogg's Crip Ya Enthusiasm, PVRIS's Burn It All Down, Sub Urban's Cradles, and Excision and ILLENIUM's Gold (Stupid Love) with Shallows) and its manifest names them; so does the owner's local `music/playlist.json`. They reach the live site with the private web image.

- The game's music player takes a track and whether it begins again at each start (`createGameMusic({src, restart})`); the game's own begins again, as before.
- `docs/plans/0.8.1.md` is now `docs/plans/0.8.2.md`.

## Deploying 0.8.1

No migration and no `.env` change. The private images must exist at the tag first: the private repository's engine and web workflows, run (or scheduled) once the tag's run has published the public `0.8.1` images; the web one now carries the cut scenes' track. Then, on the VM: `cd ~/commander-duels && git pull && bash deploy/upgrade.sh` (the pull fetches the new tag; without it the script deploys the newest tag the clone already has).
