## Added

- **Music during games** ([the game screen](../game-screen.md#the-table)). The game screen plays `/music/game.mp3` from the moment its table is on screen, fading in over 2.5 s, looping, and fading out over 1.5 s as the game ends or the player leaves. The menus, the lobbies and the practice table have no music. The browser streams the track as it plays (`preload="none"`, Range requests), so a game costs the server about 16 kB/s per listener and nothing for a player who muted it: a mute pauses the stream, and the unmute plays on from the same place. Browsers allow a page to start sound only after a click or key press; the click that starts or resumes a game is one, and a table opened by a reload plays from the player's first click or key press on it, as the sound effects do. Where there is no track (the public web image, or a local stack without `music/game.mp3`) the first request answers 404 and the table stays quiet, with no retries.
- **Settings › Sound** gains **Music volume** (0–100, 50 by default; the level is (volume/100)², as the effects') and **Mute the music**, which keeps the sound effects; **Mute all sound** now silences the music too. Both are on the Settings page and, compact, in the game's Options drawer, and the **Game menu** gains **Mute music** beside Mute. The settings stay device-local (`cd.table.v1`); a table saved before this version plays at the default level.
- **Where the track comes from.** The built site serves `/music/` as static files (`web/nginx.conf`, with nginx's own Range handling and a week's caching); the public image has nothing there. The owner's private web image (`ghcr.io/sphinxtah/commander-duels-web-sphinx:<version>`, built by the private repository from the public web image of the same version) adds `music/game.mp3`, and the live VM names it in `.env` as `CD_WEB_IMAGE` ([the live site](../deployment.md#the-web-image-with-the-music-v072)). Locally, Compose mounts the gitignored `music/` folder beside `compose.yaml` into the web container, and the dev and preview servers serve the same folder (`web/plugins/music.ts`).

## Changed

- **Pop-ups lock the page behind them** ([menus](../menus.md#every-other-page)). Every pop-up in the app is a `<dialog>` opened with `showModal()`, and browsers let the wheel scroll the page under a dialog's backdrop. Now `web/src/app/scrollLock.ts`, started with the app, watches the page for dialogs opening and closing (their `open` attribute, and an open one leaving the page as a screen unmounts) and marks `<html>` with `data-modal` while a modal one is open; `global.css` then hides the document's overflow and keeps the room the scrollbar took as right padding (`--cd-gutter`, measured as the lock goes on), so the page neither scrolls nor shifts as a pop-up opens or closes. The table's own menus (`dialog.show()`, not modal) are left alone where the browser tells the two apart (`:modal`, every supported browser); where it cannot (jsdom), every open dialog counts.

## Noted, not changed

- **Why a cost is higher.** With the music heard, the owner reported Terminate asking for {2} more than its {B}{R}: Bot 2's Jubilant Skybonder makes its flyers cost opponents {2} to target, and Skycat Sovereign flies, as did Tide Skimmer under Cast Down earlier in that game. The game was right; the payment prompt read "Pay {2}" and named no reason, and the log records no payments. For [v0.7.3](../plans/0.7.3.md): the prompt names the adjusted cost and the effects behind it.

## Not changed

- The API, its contracts (the version only), the migrations, the engine and the worker. The music is the browser's: one `<audio>` element and nginx serving a file. No API route, WebSocket frame or engine message changed.
- The sound effects and their engine (`web/src/game/sound/`); the music is a separate player (`web/src/game/music/`) that only shares the settings' mute.
- The dialogs themselves: none was changed for the scroll lock, which watches them from outside.

## Deploying 0.7.2

No migration. One `.env` addition on the VM, for the music: `CD_WEB_IMAGE=ghcr.io/sphinxtah/commander-duels-web-sphinx` (the same ghcr.io login as the engine's). Without it the site runs the public web image, which has no music, and everything else works. The engine did not change, but `deploy.sh` pulls the private engine image at the tag, so `commander-duels-engine-sphinx:0.7.2` must be built too, and now `commander-duels-web-sphinx:0.7.2` as well (the private repository's two workflows). Once the tag's run has published the `0.7.2` images and both private images exist, on the VM: `cd ~/commander-duels && git pull && bash deploy/upgrade.sh`.
