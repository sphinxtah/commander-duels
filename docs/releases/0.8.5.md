# v0.8.5: the lesser fixes and the tutorial's follow-ups

A patch version, opened and closed on 2026-11-01. The next version was v0.8.6 ([release notes](0.8.6.md)), then v0.8.7 ([the plan](../plans/0.8.7.md)).

## Scope agreed for this version

The owner, 2026-11-01: "Lets start v0.8.5 by addressing the leftover bug fixes from earlier." From v0.8.3's search for bugs, the lesser findings (v0.8.3 took the most serious twelve), and from the plan's start questions:

- **The lesser findings, triaged:** every one with an effect on players, data or deploying; six with none (SysOp's or development's only, or no exposure beyond what the public repository already shows) stay for v0.8.6.
- **The session cookie** is renamed with the `__Host-` prefix, so every player signs in once more after the deploy.
- **The development stack** gets its own Compose project name, with a one-time copy of the local volumes.
- **The v0.8.4 tutorial's follow-ups:** the guided game's words and pace, the tour's bubbles on a phone, and the tour pointing at Decks and the Play page.

## Fixed

### Games and tables

- **A game start that can't be followed is closed.** The engine's answer to a new game is checked (its id, a token for each human seat, a deck for each seat) before anything is recorded, and any failure while recording closes the engine game and marks a recorded game interrupted. Before, a malformed answer or an error other than the database's could leave a game running that nothing followed. One helper does this for practice games, tables, queues, rematches, match games and campaign duels.
- **A new tab gets the whole log.** A snapshot published while a new connection was opening could arrive before its full page, which was then dropped; the log started mid-stream until a reconnect.
- **Locks are kept only while in use.** The per-player, table, game and match locks were never removed.
- **One API process.** The API takes a PostgreSQL advisory lock at startup; a second process on the same database refuses to start and says why ([games](../games.md)).
- **A signed-out tab can't take a seat.** Taking or releasing control and resyncing check the session at once, not at the next minute's check.

### Economy, campaign and auctions

- **The finale's spoils wait for their card.** If the private finale is won before its custom card is uploaded, the win, seal and chapter count, and the spoils are paid in full on the first win after the upload. Before, the public stand-in was paid and the spoils could never be paid again. The spoils now also read the deck the bot was served.
- **Auctions settle one at a time.** One failing auction no longer stops every other settlement; a sale settled because an auction's time ran out is recorded as the system's, not under the address of whoever was reading the market.
- **Print runs hold for SysOp too.** SysOp can list a printing with a print run only from copies granted to it.
- **Grants are given once.** Giving tokens or packs from Administration takes a key, as purchases do; a double-click grants once ([tokens](../tokens.md), [shop](../shop.md)).

### Identity

- **Sign out everywhere can't be undone by a rotation** happening at the same moment.
- **The session cookie is `__Host-cd_session`**, on `/`, secure, with no domain, so no other site under the same domain can set one the API would read. The old `cd_session` is cleared at sign-in and sign-out. Plain HTTP on another host than localhost (`CD_COOKIE_SECURE=false`, refused in production) uses `cd_session_http` ([identity](../identity.md)).
- **Administration shows unverified addresses** next to an account's email.

### Decks, search and the catalog

- **Two saves of a version at once** both succeed in order, instead of one failing with a server error.
- **`year:`** takes a whole year from 1 to 9999; `year:0`, `year:nan` and the like are search errors, not server errors.
- **An import of more than 400 entries**, and a draft naming a card or printing that doesn't exist, are refused with a message instead of a server error.
- **A staff suspension made during the daily import stands.**

### The engine

- **A generator for each game.** XMage drew every random number from one generator for the whole process, and seeding a new game reseeded it for every game running. XMage patch 0010 gives each game its own, so a seed repeats its game while others run, and no game's stream follows another's seed ([patches](../../engine/xmage/patches/README.md)).
- **A foretold card is its owner's to see.** A face-down exiled card is shown to a player XMage lets look at it (foretell, hideaway, "you may look at it" exiles), and still to no one else ([the human seat](../engine/human-seat.md)).
- **Views are built on the game thread only.** An event XMage fires on another thread now marks the views stale for the game thread to publish.

### The web app

- **Save a version** stops when the draft didn't save, and reopens an unresolved conflict instead of saving over it.
- **The campaign's Auto and text speed** are one shared setting, so a change in a cut scene isn't undone from the map.
- **The game's connection** pings every 25 seconds and when the page is shown again, and reconnects when no answer comes, instead of waiting on a connection a sleeping computer left half open.
- **Music** stops for the visit only when its track is missing; a network or decoding error lets it try again.
- **A refused security token during a reconnect** is fetched again once, instead of ending the game.

### Deploying and CI

- **`update.sh main`** deploys main's commit, by its `sha-` tag, with that commit's kit.
- **The deploy keeps a record** (`deployed.env` beside `.env`) of the tag and database revision it last ran and the dump to restore to go back; a fall-back uses it, and when going back is impossible the script prints the exact restore command.
- **Dumps are checked before they are kept** (a full read of the archive) and before older ones are pruned, and the dumps a rollback needs are never pruned.
- **The worker reports a heartbeat**, and a deploy waits for it to be healthy.
- **`bootstrap-vm.sh`** keeps an installed kit.
- **CI** checks the production Compose file, pins every action to a commit, reads with read-only permissions by default, and an outdated publish no longer moves the `main` tag back.

## Changed

- **The tutorial's guided game** is checked line by line: the command zone, the commander tax, lethal damage, the skipped first draw and the deck's size are stated exactly, and words like tap, graveyard, resolve and exile are explained where they first appear. It has twenty-one lessons (the docs said eighteen). Play on its own waits for the board to settle and for the lesson's length in words; with reduced motion the frames are still pictures. The narration sits at the lower right, clear of the opponent's life and commander damage.
- **The tour's bubbles on a phone** place themselves below, above or beside what they point at, stay inside the window and below the top bar, and follow rotation and scrolling ([the tutorial](../menus.md#the-tutorial-v084)).
- **The tour goes on to Decks and the Play page** after the auction house, ending at the practice table's Start the game. Settings › Tutorial can run those two steps alone. Migration 0034 adds their stages.
- **The development stack is `commander-duels-dev`**, so a Compose command in a clone on the live server can never touch the live stack or its volumes.

## Deploying 0.8.5

Migration 0034 widens the tutorial's stage check, so v0.8.4 keeps serving while it runs; no `.env` change. Every player signs in again once, because the session cookie has a new name. The private images must exist at the tag first (the private repository's engine and web workflows, run once the tag's run has published the public `0.8.5` images). Then, on the VM, as always: `cd ~/commander-duels && git pull && bash deploy/upgrade.sh`. This deploy writes `/srv/commander-duels/deployed.env` for the first time.

**The local stack, once:** the development stack's new name gives it new volumes. Before the first `docker compose up`, run `python scripts/copy_dev_volumes.py` in the project folder: it copies the database, the card image cache and the catalog files from the old volumes, refuses to overwrite, and deletes nothing ([README](../../README.md#start-with-docker)).
