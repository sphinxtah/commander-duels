# v0.6.3: longer and unlimited auctions, and a blocking fix

A patch version, as the owner named it, opened and closed on 2026-10-25 (tag `v0.6.3`). This follows [the v0.6.3 plan](../plans/0.6.3.md).

## Scope agreed for this version

The owner, 2026-10-25: "only one change: Auctions get an option for unlimited time listing. Also add 7 days and 30 days as options." Asked how an auction with no end settles its bids, the owner chose **Buy Now only** ([the plan](../plans/0.6.3.md#decisions-at-the-start-of-v063)). Added mid-thread by the owner, before the close: a blocking bug found in a game.

## Added

- **7 days and 30 days** in Tivit's Auction House, beside 1 hour, 3 hours, 12 hours, 24 hours and 3 days. They work like the other lengths: bids, the 30-second anti-snipe, and settlement at the end ([the auction house](../auctions.md#a-listing)).
- **Unlimited listings**, Buy Now only, as eBay's Good 'Til Cancelled:
  - The Sell dialog's "Unlimited" asks only for a Buy Now price (at least 1 token); the starting bid and the Buy Now checkbox are hidden. Its summary says the listing is Buy Now only, with no end.
  - An unlimited auction takes no bids (`409 buy_now_only`) and never expires. It runs until someone pays Buy Now, the seller withdraws it (at any time, as it has no bids), or SysOp cancels it.
  - Its panel shows the Buy Now price, "No end" for the time left and only the Buy Now button. Tiles, rows and the administration log say "No end".
  - The market sorts unlimited auctions after every auction with an end, and the "time left" filter leaves them out. Relisting can change the length either way.
  - In the API, `duration` takes `7d`, `30d` and `unlimited`. An unlimited auction's `ends_at` is `null`, and its `starting_bid` equals its `buy_now`. Listing one without a Buy Now price is refused (`422 buy_now_required`).

## Fixed

- **Blocking with a creature that can block no attacker** (the owner's report: Varragoth, Bloodsky Sire could be chosen to block, but no attacker could be picked; clicking the attacker only enlarged it, and Done led back to the same choice). XMage offers every creature able to block anything, and only after one is picked asks which attacker it blocks. When the creature can block none of the attackers (a flier, an attacker it is not allowed to block, or one attacking someone else), that question offered nothing, and Done asked for blockers again, forever. The engine now offers only creatures that can block at least one attacker, using XMage's own test, so a creature offered always has an attacker to choose ([the human seat](../engine/human-seat.md)). New engine test: `BlockersTest`.

## Deploying 0.6.3

No `.env` change. One migration (`0030_auction_lengths`), which `upgrade.sh` runs. It widens `auctions.duration`, lets `ends_at` be null for unlimited auctions and adds their checks. The engine changed (the blockers fix), so the private engine image `0.6.3` must be built too. Once the tag's run has published the `0.6.3` images and the private engine image exists, on the VM: `cd ~/commander-duels && git pull && bash deploy/upgrade.sh`. Afterwards, the Sell dialog offers 7 days, 30 days and Unlimited, and a creature offered as a blocker always has an attacker to choose.
