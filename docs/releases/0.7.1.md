# v0.7.1: amateur bots at low skill, and the auction house's sections fold

A patch version, closed on 2026-10-31 (tag `v0.7.1`). The owner asked for both changes on the evening of 2026-10-30 as additions to v0.7.0, already tagged; this session's GitHub access could create a tag but not move one, so the owner chose to tag them as v0.7.1. The music planned for v0.7.1 moves to [v0.7.2](../plans/0.7.2.md).

## Scope agreed for this version

The owner, 2026-10-30: "One more thing to fix in this version: The bot difficulty isn't spread properly. 6 difficulty is fine, but 1 difficulty is still very difficult... the 1 bot makes intelligent choices, when it should be playing like an amateur. Fix that, tag, push and officially close the version." And: "Make the sections collapsible. I have to scroll a really long time to reach the sold cards. Default is collapsed." ([the v0.7.1 plan](../plans/0.7.1.md)).

## Changed

- **The bots' difficulty is spread.** The owner, 2026-10-30: "The bot difficulty isn't spread properly. 6 difficulty is fine, but 1 difficulty is still very difficult... the 1 bot makes intelligent choices, when it should be playing like an amateur." XMage's skill changes little a player feels (its search is as deep at skill 1 as at 4, and its attacks, blocks, targets and choices are the same heuristics at every skill), and v0.6.5's flat share of passed priorities mostly delayed a spell to the next main phase. Now a `FairBot` has a `Profile` for its skill, the habits of a weaker player: it lets chances pass (30% of its own main phases and 70% of other priorities at skill 1), plays a land or a random castable spell instead of what the search prefers (50%), holds attackers back (35% each, so lethal attacks are missed) or sends creatures into blocks (30% each), and declares no blockers (45%, unless the attack would be lethal). Each share falls steeply with the skill: about 72% of it at skill 2, 46% at 3, 25% at 4 (the default table bot stays a decent player), 9% at 5 and none at 6, which is XMage's AI as it was. Skills 1 to 3 also think one second per level instead of three, which spares the server. The search and its depth are unchanged, so what the bot does play is still legal and sound ([fair bots](../engine/fair-bots.md#skill-and-habits-v071)).
- **The auction house's sections fold.** The owner, 2026-10-30, with a hundred active listings: "Make the sections collapsible. I have to scroll a really long time to reach the sold cards. Default is collapsed." On the transfer list and the transfer targets each section's heading is now a button, every section starts folded, and the count and the Clear button stay on the folded bar ([the auction house](../auctions.md#transfer-list)).

## Not changed

- The API, its contracts (the version only), the migrations and `.env`. The engine image changes (the bots), so the tag's run builds a new one and the private engine image must be rebuilt from it.

## Deploying 0.7.1

No `.env` change and no migration. The engine changed, so the tag's run builds a new engine image, and `deploy.sh` pulls the private engine image at the tag, so `commander-duels-engine-sphinx:0.7.1` must be built from it ([the live site](../deployment.md#the-engine-with-the-custom-cards-v040)). Once the tag's run has published the `0.7.1` images and the private engine image exists, on the VM: `cd ~/commander-duels && git pull && bash deploy/upgrade.sh`.
