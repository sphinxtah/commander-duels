# v0.0.6: authenticated game routing

The last system-building step before v0.1.0's testing interface. A signed-in account starts a practice game against bots through the API and plays it over a WebSocket. The API keeps the engine's seat tokens, so the browser never sees them, and one tab at a time controls the seat. Every view still comes from the engine's authorized seat views. SysOp's game powers exist now: practice games, an inspection view of every hand and library, and test decks from any card the engine implements. The site also carries the owner's logo. There is still no game interface; scripts play the games. Design and protocol are in [games through the API](../games.md).

## Scope agreed for this version

Agreed on 2026-10-19, every recommended option:
- **Transport:** WebSocket now, the scope's protocol (NET05–NET07).
- **Formats:** Legacy against a bot, and Commander against one to three bots.
- **SysOp's any-card decks:** in this version, as a deck list on SysOp's practice games.
- **Persistence:** games, seats, owners and results in PostgreSQL.
- **Small fix:** PostgreSQL's host port is configurable.

Added mid-thread by the owner: the logo, `commander.duels.logo.png` with its words and `commander.duels.logo.nowords.png` without, for the site.

## Included

- **Practice games through the API:**
  - `POST /api/v1/practice-games`: format, your fixture deck, the bots and their decks, bot skill and turn cap.
  - `GET /api/v1/practice-games/options` lists the formats, bot counts and decks.
  - `GET /api/v1/games` lists your games. `GET /api/v1/games/{id}` returns a game with its seat's current snapshot. `POST /api/v1/games/{id}/close` ends one.
  - Limits: one running game per account (`CD_GAMES_PER_ACCOUNT`; SysOp unlimited), two in the API (`CD_GAMES_MAX`), and the engine's own cap.
- **Seat ownership (AUTH07's match half, T29's match case):**
  - The API keeps the engine's seat tokens in its memory and records which account owns which seat.
  - Every other account gets 404 for the game, its WebSocket and its commands.
- **The game WebSocket (NET05–NET07):**
  - `/api/v1/games/{id}/events`, authenticated by the session cookie, the site's own `Origin` and the session's CSRF token in the first message.
  - It pushes each new revision of the seat's snapshot, unchanged from the engine, with the new log lines. Clients resynchronize by revision.
  - Commands use the engine's envelope: action ID, expected revision and prompt ID.
  - Signing out, a revoked session or an expired one closes the connection.
  - The web proxy and Vite pass the upgrade through.
- **The controller lease (AUTH07).** One connection per seat commands. Taking control from another tab moves the lease, and the old tab observes and is refused.
- **Resends run once (T14).** A command resent with the same action ID returns its first result and applies nothing. That holds after a dropped connection too.
- **The engine's service routes:**
  - Service games under `/v1/service`, only with `CD_ENGINE_SERVICE_TOKEN` (shared by the API and the engine, at least 32 characters).
  - Seat tokens still select seats. The service token alone closes a game, inspects it and looks up card names.
  - Service games and development games share the cap but never each other's routes.
  - The development endpoints stay for scripts.
- **SysOp's game powers:**
  - **Practice games** against bots.
  - **The inspection view** (`games.view_concealed`). Every player's hand and library in order, the public view and every seat's deck.
    - It is a new engine view type, built field by field, with its own [contract](../../contracts/engine-inspection.schema.json).
    - The engine builds it only while XMage waits for a human seat, when the game's state holds still.
    - SysOp gets it over the WebSocket or `GET /api/v1/games/{id}/inspection`, for any game. Every opening is audited.
  - **Deck lists from any card** (`cards.any`).
    - Text with one card per line. Names match ignoring case, unknown names come back together, and no format rules apply.
    - Any seat may have one: SysOp's own, or a bot's.
    - `GET /api/v1/cards?q=` looks up names in the engine's card database.
  - **Observing** another player's game, and closing it, is audited.
- **Data.** Migration `0003_games` adds `games` (format, status, creator, settings, result) and `game_seats` (player, owner, deck or deck list). An API restart marks running games interrupted and closes them in the engine.
- **The logo:**
  - The full logo on the Play page.
  - The logo without words as the sidebar mark, the favicon and the home-screen icon.
  - `scripts/brand_assets.py` makes the web sizes from the owner's files, which stay outside the repository.
- **Tooling:**
  - `scripts/api_practice_game.py` plays a whole game through the API as SysOp. It checks every snapshot and inspection against the contracts and the leak checks, and proves the lease and a resend along the way.
  - CI's engine job runs a Legacy and a Commander game with it.
- **Infrastructure:**
  - `CD_DB_PORT` moves PostgreSQL's host port when Windows reserves 5432. This computer now uses 15432, with no override file.
  - New dependency: `websockets` 17.2, for Uvicorn's WebSockets and the scripted client.
  - Tests no longer read a developer's `.env`.

## Not included
