# v0.0.4: Commander tables and the multiplayer seat bridge

Third slice of milestone M0. The v0.0.3 seat bridge now seats two to four players, any mix of human seats and XMage computer players, in Legacy or Commander. Every human seat has its own token, prompt state, revision and authorized view, and the leak checks run for every human seat. The views carry the command zone, commander tax and commander damage straight from XMage's watchers. Every request the fixture decks reach is a typed prompt, now including modes, X values, trigger order and piles, and a read-only spectator view shows public information, optionally delayed. Gameplay stays unavailable to players: these are development games driven by scripts, there is no game UI, and the FastAPI application still refuses game actions. Design and findings are in [Commander tables](../engine/commander-tables.md).

## Scope agreed for this version

Agreed on 2026-10-18, with every recommended option:
- **Order:** engine first. The route to v0.1.0 stays v0.0.5 identity, v0.0.6 authenticated routing, then the testing UI.
- **Tables:** Commander at two, three and four seats, with mixed human and bot tables at each size.
- **Decks:** four invented Commander decks of simple cards.
- **Two-Headed Giant:** a written feasibility assessment with a recommendation; no implementation.
- **Added before closing (same day):** the remaining prompt families (modes, X values, trigger order, piles) and spectator views. Engine dependency hygiene (SEC06) and the AI audit (AI02/AI05) stay out.

## Included

- **Commander games:**
  - Two seats use XMage's `CommanderDuel`, labelled as the scope's two-seat Commander profile rather than Duel Commander. Three and four seats use `CommanderFreeForAll`.
  - All tables start at 40 life with the London mulligan.
  - Mulligan and first-draw rules follow the table size: with two seats there is no free mulligan and the starting player skips the first draw; with three or four the first mulligan is free and nobody skips.
  - The engine image now also builds `Mage.Game.CommanderDuel` from the pinned commit, still with no patches.
- **Fixture decks:**
  - Four 100-card, mono-coloured Commander decks (white, blue, red and green), validated with XMage's `mage.deck.Commander`. No card name appears in two decks.
  - Seven cards reach the rarer prompts: Valorous Stance, Abrade, Blaze, Mistcutter Hydra, Soul Warden with Attended Knight, and Fact or Fiction.
- **Seats and tokens:**
  - `POST /v1/games` takes a `format` and a list of `seats` in turn order, each human or bot, with an optional fixture deck.
  - The response returns one token per human seat, once. Each token selects its seat; no request field can.
  - A seat's revision moves only when its own view or prompt changes.
  - A seat sees only its own deck name.
  - Turns pass in seat order.
- **Eliminations:**
  - A seat that concedes leaves the game, and at three or four seats the others play on. Its status becomes `eliminated`.
  - When every human seat is out and bots remain, the game ends as `humans_eliminated`.
  - Closing ends the game for every seat.
  - Results list `conceded_seats`.
- **Views:**
  - `opponents` replaces `opponent`.
  - Each player state adds its colour identity, its command zone, and per commander: zone, object, casts from the command zone, tax and combat damage dealt to each seat.
  - A commander in a hand or library is `hidden` to everyone but its owner.
- **Prompts:**
  - New kinds: `choose_defender` (which player or planeswalker an attacker attacks, naming the attacker), `choose_ability` (planeswalker loyalty abilities and other ability choices) and `choose_choice` (colours, the order of replacement effects; at most 64 entries).
  - Also new: `choose_mode` (modal spells), `choose_amount` (X and other numbers, answered with a custom amount or the minimum), `order_triggers` (simultaneous triggers with different texts) and `choose_pile` (with each pile's object ids).
  - Commander's "move it to the command zone?" is a `yes_no` with XMage's labels.
  - Only choices longer than 64 entries stay `unsupported`.
- **Spectators (NET14):**
  - Every game has one read-only `spectator_token`.
  - Its snapshot has no seat, prompt, `you` or hand, and lists every player. Commands and close return 403 `read_only`.
  - `spectator_delay_seconds` (0–300) delays the spectator's view, log and result.
- **Fixes found on the way:**
  - The engine now answers XMage's current player object. XMage copies players when it restores a state after a cancelled cast, and an answer to the old object stalled for 30 seconds and was dropped. v0.0.3 had the same exposure.
  - XMage's turn order is the reverse of the order players are added; the engine corrects for it.
  - Other seats' views are published before a seat's prompt opens, so answers no longer wait in XMage's 100 ms steps.
- **Contracts:**
  - The seat-view schema gains opponents, commander fields, the new prompt kinds and `piles`, `eliminated`, `humans_eliminated`, `conceded_seats` and spectator snapshots. Seats now run 0–3.
  - The Python contract tests reject a hidden commander's object, a fifth seat, odd commander tax and leftover Legacy deck fields. They also reject a spectator snapshot with a prompt, a `you`, a hand or looked-at cards, and a pile holding an XMage id.
- **Tools:**
  - `scripts/engine_human_game.py` takes `--format` and `--seats` and plays every human seat on its own thread with its own token.
  - It checks every payload, including that no seat is told another seat's deck.
  - It verifies that another seat's token cannot answer a prompt.
  - A spectator thread watches every game with the spectator token, and `--spectator-delay` sets the delay.
  - Answers to `choose_amount` are sometimes a custom number.
- **Tests and CI:**
  - New JUnit suites:
    - `CommanderGameTest`: fixture legality, scripted tables at two, three and four seats, the rules profile per table size, the all-humans-out stop and the spectator delay.
    - `CommanderScenarioTest`: a deterministic four-human game for T07 and T08.
    - `PromptFamiliesTest`: a deterministic four-human game that reaches every new prompt family.
  - Every spectator view is checked like a seat's.
  - The Legacy suite and the HTTP tests move to the multi-seat API, and a new HTTP test proves token isolation between seats.
  - The CI engine job adds a schema-checked four-seat Commander game (two humans, two bots).
- **Docs:**
  - New: [Commander tables](../engine/commander-tables.md) and [Two-Headed Giant feasibility](../engine/two-headed-giant.md).
  - Updated: the human seat, architecture, backlog, README, the dependency ledger and the v0.0.4 plan, which now records the decisions.

## Not included

- A browser interface, sign-in, seat ownership, and API routing of game actions.
- Two-Headed Giant itself. XMage has no team game type; [the note](../engine/two-headed-giant.md) recommends a one-version spike on a patched XMage after v0.1.0.
- Lobbies, readiness and Rule Zero settings (NET02–03, FMT03–04).
- Timers and recovery.
- The AI hidden-information audit (AI02).
- Choices longer than 64 entries (naming a card).
- Spectator delays counted in turns, and replays.
- Engine dependency hygiene (SEC06).

Gameplay remains unavailable to players.
