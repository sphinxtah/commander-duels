# v0.0.2: XMage headless engine spike

First slice of milestone M0 (discovery and engine proof). The engine builds XMage from a pinned commit on Java 21 and plays complete Legacy games between two XMage computer players with no UI. Gameplay stays unavailable to players. Measurements and findings are in [docs/engine/xmage-spike.md](../engine/xmage-spike.md).

## Included

- **XMage pin:** release tag `xmage_1.4.62V1`, commit `eb69d05b88142b5c4eec4869bcb23a0fec13c091` (2026-10-03), recorded in `engine/xmage/pin.properties`. The engine image fetches only that commit (shallow and partial), keeps XMage's MIT licence in `/app/licenses`, and needs no upstream patches.
- **Maven build on Java 21:** the image installs `Mage`, `Mage.Common`, `Mage.Sets`, the "Computer - mad" AI, the Two Player Duel and Commander free-for-all game types, and the constructed deck validators, compiled with JDK 21 (`--release 21`).
- **Multi-stage image:** Maven and JDK 21 build stages, plus a JRE 21 runtime that runs as uid 10001. XMage rebuilds only when `engine/xmage/` changes.
- **Card database:** built at image-build time (93,992 printings, 32,739 distinct names). The engine is ready in under a second.
- **Engine service:**
  - `/health` reports the engine state, the pinned XMage build and the card counts, with `gameplay_available: false`.
  - `/ready` returns 503 until the card database is open.
  - Development-only `POST /v1/bot_match`: a Legacy Two Player Duel between two "Computer - mad" players with fixture decks (mono-red burn and mono-green creatures, both Legacy-validated). It has a seed, a turn cap, a wall-clock budget and AI skill, all clamped. One match runs at a time, and every game ends as `completed`, `turn_limit`, `timeout` or `error`.
  - Other `/v1/*` operations still return 503 `engine_not_integrated`.
- **Honest results:** XMage's "technical winner" endings after internal errors are reported as `error`, and recovered engine errors are counted.
- **API:** `EngineStatus` passes the new health shape through and still reports `unavailable` for anything invalid, including any claim of gameplay. The gameplay capability's reason now says the engine runs internal bot games only. Bootstrap capabilities and `/formats` stay unavailable.
- **Compose:**
  - Engine healthcheck on `/ready`, explicit heap (`-Xmx768m`) and memory limit (1.5 GB).
  - H2's auto-server listener bound to loopback.
  - No engine port on the host or through the web proxy.
- **Tools:** a documented one-line bot match command from the API container, and `scripts/engine_bot_matches.py` for repeated runs.
- **Tests and CI:**
  - 29 JUnit tests (boundary, input limits, concurrency, real seeded games, turn cap, timeout cleanup).
  - API tests for the new status shape.
  - CI builds the engine image with the GitHub Actions layer cache and smoke-tests it in Compose.
- **Docs:** the spike findings, architecture, backlog, README, asset provenance and engine dependency licences (`docs/engine/xmage-dependencies.csv`).

## Not included

Human seats, prompt bridging, authorized per-seat views, any game UI, four-seat Commander, Two-Headed Giant, action journals, snapshots, recovery, Scryfall import, card coverage, sign-in, decks and the TeaVM offline probe. Gameplay remains unavailable to players.
