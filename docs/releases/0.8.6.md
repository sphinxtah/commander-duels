## Added

### How to play

- **The guide** ([how to play](../how-to-play.md)): Magic in plain words, in twelve chapters and thirty-six topics: what Magic is, winning and losing, the golden rules; reading a card (Serra Angel with numbered pins and arrows to each part's name), the kinds of cards, the five colours; lands and mana, paying a cost; the zones; the steps of a turn; casting, priority, the stack, targets, countering; the three kinds of abilities, planeswalkers, counters and tokens; combat step by step, attacking, blocking, combat damage with first strike, trample, deathtouch and lifelink; the common keywords and keyword actions; Commander's rules, the commander tax, commander damage, games of three or four; starting a game and mulligans, the checks the game makes, how long effects last; and the Commander Duels table itself. Each topic has worked examples with their cards and a result, and names the official rules it explains.
- **Real cards.** The guide's thirty-three example cards are drawn from the API's Scryfall cache, over a text frame of their words. `GET /api/v1/how-to-play/card-images` serves those names, and only those, to anyone, so the guide's cards show signed out too.
- **Screenshots of the real table**, taken from the tutorial's guided game by `web/e2e/how-to-play-shots.spec.ts`, with numbered pins where each place is, measured on the page: the zones, the commanders, attacking, blocking and the stack.
- **The official rules**, whole: sections, chapters, rules with their examples, and the glossary, with the effective date and Wizards of the Coast's name, each rule linkable (`#how-to-play/rules/702.19b`) and every reference to another rule a link. The text is Wizards' plain-text release, parsed in the browser (`web/src/howToPlay/rules.ts`, tested on a made-up fixture in the same format, and on the official file when the local `rules/` folder has it).
- **Search**: the guide's topics by their words, and the official rules by number or by words, with the glossary's terms.
- **Where it opens**: the account's menu in the upper right; any `#how-to-play` address signed out, as a page of its own; "What's this?" under every prompt at the table, to the topic of that kind of choice, in a new tab; "More in How to play" on each page of the Novice's refresher and each lesson of the guided game.
- **The official text's place.** The owner's private web image serves `/rules/comprehensive-rules.txt`; the public images answer 404, and How to play says "Official rules not included in this build" with a link to Wizards' rules page. Locally, the gitignored `rules/` folder beside `compose.yaml` (Compose mounts it; the dev server serves it). The private repository checks Wizards' rules page every Monday at 06:17 in Phoenix and opens a pull request for a new release; merging it builds the private web image.

### Passive bots for SysOp

- **A switch in the Inspection drawer** of SysOp's own practice game or campaign duel with no other human seat: passive bots only draw, pass and discard to hand size; no lands, spells, abilities, attacks or blocks, they keep their opening hand and decline every optional choice but sending their commander back to the command zone ([the game screen](../game-screen.md#passive-bots-v086-administrators-v087)). One switch for every bot, from each one's next decision, either way, at any time; the log says "Bots set to passive." or "Bots set to normal.".
- **Nothing pays out** once a game's bots have been passive: no win, tokens, quests or achievements, and in a campaign duel no spoils or chapter rewards, though a won duel records its seal and opens the next ward. A later win without passive bots gives the spoils as a first win would.
- **SysOp's alone**: the API refuses the switch from any other account (403) and anywhere else (409); nobody else sees anything new. `PUT /api/v1/games/{id}/bots`, audited as `game.bots_passive` and `game.bots_normal`; migration 0035 adds `games.bots_passive` and `games.passive_bots_used` ([games through the API](../games.md#sysops-powers)).

## Fixed

The bug hunt's last six findings:

- **SysOp's inspection reads the game only while it waits** (E4). It was built whenever a prompt had been published, which the game thread does a moment before it actually stops to wait for the answer; now the human seat's player reports XMage's own wait, and the game thread must be parked ([games through the API](../games.md#sysops-powers)).
- **The development close** (E5), on the engine's development routes only: only the first human seat, the creator's, closes the whole game; any other seat's token is refused (403) and concedes instead ([the human seat](../engine/human-seat.md)).
- **SysOp's routes off its networks** (I2): a wrong method (`GET /api/v1/sysop/login`) and a trailing slash (`/api/v1/sysop/entrance/`) answer as any missing path, where they answered 405 and a redirect ([identity](../identity.md)).
- **A CSRF token outside ASCII** in a game's or the chat's WebSocket hello is refused as a wrong token, instead of failing with an error in the server's log (I5).
- **Older answers never replace newer ones** (W6): the practice table's list of games, its card name search, and the rematch's offer (a poll sent before an offer, answering after it, brought the old state back).
- **`push.sh` checks its host** as it checks its tag (P10): the tag was checked before it reached the VM's shell since v0.8.3; `CD_DEPLOY_HOST` is now checked too, so it can never be read by ssh as an option.

## Deploying 0.8.6

Migration 0035 only adds two columns with defaults, so v0.8.5 keeps serving while it runs; no `.env` change. The private images must exist at the tag first (the private repository's engine and web workflows, run once the tag's run has published the public `0.8.6` images); the private web image of 0.8.6 carries the official rules. Then, on the VM, as always: `cd ~/commander-duels && git pull && bash deploy/upgrade.sh`.

**Once, in the private repository:** Settings → Actions → General → Workflow permissions → "Allow GitHub Actions to create and approve pull requests", so the weekly check can open its pull request. Its first run can be started by hand (Actions → Official rules update → Run workflow): with the committed release still current, it changes nothing.

**The local stack:** copy the official rules to `rules/comprehensive-rules.txt` beside `compose.yaml` (the private repository has it) and run `docker compose up -d` again, so the web container mounts it.
